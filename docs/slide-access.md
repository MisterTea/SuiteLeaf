# Slide reading order

Each slide object has an id. `applyMaster` copies a master's alternative text onto an object with the same id, unless that object has `altOverride`. The slide's own text then stays. The master list and the slide list passed in are not changed.

`readingOrder` uses the stored id list. An id that is not on the slide is reported as missing. The note says `Reading order names an object that is not on this slide.` and does not repeat that id. Objects left off the list are appended in their slide order, so nothing is skipped silently. An image with no alternative text says `This image needs alternative text.` The image id is not in that note. An image marked decorative is left out of the reading order and does not need alternative text. Its alternative text is not read. The image passed in is not changed. The accessibility panel has a Decorative checkbox for an image, shape, video, or audio object. Checking it stores that flag.

The pieces and the order are plain JSON. A slide may store `readingOrder` as object ids. The slide toolbar button Accessibility lists that order when it is present, and otherwise lists the objects in their slide order. A video or audio clip is in the reading order. Without alternative text it says `This video needs alternative text.` or `This audio needs alternative text.` Without caption text it says `This video has no captions.` or `This audio has no captions.` A still picture that is not an embedded image says `This video's picture is not an embedded image.` or `This audio's picture is not an embedded image.` An embedded still with no alternative text says `This video's picture needs alternative text.` The picture address is not in those notes. Each remaining object has a text field. An image field edits that object's alternative text and leaves the other objects unchanged. A text field edits that object's text. Earlier and Later move that object in the reading order without dragging. The first object cannot move earlier. An id that is not on the slide is left out of the new order. The lists passed in are not changed. An image description is written into the PowerPoint file and read back. A SuiteLeaf marker used for an SVG or an image layer is not shown as that description.

A PowerPoint export writes `readingOrder` as its own list in the slide XML, using the shape ids in that file. Import reads that list back onto the slide. Ids that the file cannot name, including ids with characters outside letters, digits, `_`, and `-`, are left out of the PowerPoint list. The list is not speaker notes. Audio and video are not given a place in that list.

Applying a theme also restyles an existing master. The master background becomes the theme background. A footer uses the theme body font and colour. A master object marked as a hand-set colour keeps that colour. A deck with no master stays without one. The master passed in is not changed.

A slide text box uses its own font size, family, color, and text. When it has none, it uses the master object with the same id, or the same placeholder. Blank text uses the master text, so changing that master text changes the box. A box that stores its own words keeps those words. A decorative master object does not supply that text. A decorative text box is also skipped when the title color is read. The next text box supplies the color, or the default black when every text box is decorative. The lists passed in are not changed.

`animationSequence` is the click order for the slideshow and for the PowerPoint timing. An object with a stored order uses that number. An object with an animation and no stored order uses its place on the slide, starting at 1. An object with no animation is left out. The list passed in is not changed. Two objects with the same order are one click. The slideshow reveals both, and the entrance plays on the first. PowerPoint writes the second as `withEffect`. An object marked `after` stays on that same click and starts when the previous entrance finishes. PowerPoint writes it as `afterEffect`. Reduced motion shows it immediately. The animation pane uses those same click numbers. Welcome and a photo marked after are both click 1, and the photo says after previous. A note with no animation is left out. The slideshow was not opened in the browser. The animation pane was not opened in the browser. An entrance can store a length. `1500` stays `1500` when the deck is saved and opened. A missing length is 600 milliseconds. A length of `9000` plays as 5000, and a length that is not a number plays as 600. The slideshow sets that length on the entrance. The animation pane lists that same length: `1500 ms`, `5000 ms` for a stored `9000`, and `600 ms` when no length is stored. Preview uses that same entrance class and length. Welcome is `fade-on-click-enter` for `1500ms`. A photo marked after is `fly-on-click-enter` with the after-previous delay, for `5000ms` when `9000` was stored. The slideshow was not opened in the browser. The animation pane was not opened in the browser.

A blank slide title is `This slide needs a title.` A title that is only an invisible character is the same. A title that starts with that character, or keeps it inside the word, still has a title. Title text of `#ffff00` on `#ffffff` is below 4.5:1, so the note says the title color does not contrast with the slide background. `#000000` on `#ffffff` has no contrast note. A three-digit color is expanded, so `#000` on `#fff` has no contrast note and `#eee` on `#fff` does. A color that is not `#rrggbb` says the slide colors are not hex colors, and the note does not repeat that color. The accessibility panel shows these notes when it is given a title and colors. The title box named Beds with a word color of `#ffff00` is the color that is checked, not a fixed black and not the next text box. A title color of `secret-value` is still not a hex color, and the note does not repeat that word. When the slide has no text box, the check uses `#111111`. The panel was not opened in the browser. This is not a WCAG conformance claim.

Audience screen opens a window with the slide’s visible text and no speaker notes. Welcome is the heading, and `North beds` and an image description `Tomato` follow it. A blank screen says `The screen is blank.` and does not include that text. A slide with no visible text is `Slide 2` when that is the second slide. Moving to the next slide replaces that window: Welcome is removed and `North beds` becomes the heading. A blank title uses the master title text, so the audience window can show `Garden club`. A title that stores `North` stays `North`. The slideshow was not opened in the browser. An object that waits for a click stays off that window until it is revealed. Welcome is shown first. `secret-value` is not in the window until that click, and it is shown after the click.

Changing a video or audio description in the accessibility panel stores that description. The clip address stays on the clip. An image or shape description is stored the same way. The slide passed in is not changed by the comparison.

A table is a text field in reading order. `Plot` and `North` on the first row, and `Beds` and `10` on the second, are `Plot`, a tab, `North`, a new line, `Beds`, a tab, and `10`. Changing `North` to `South` stores that row. A line with a different number of cells says `Keep the same number of columns.` and does not store the change. That sentence does not include the typed text. The table passed in stays as it was. The accessibility panel was not opened in the browser. This is not a WCAG conformance claim.

A video can store a caption. Saving the deck and opening it again keeps `North beds`. The clip's caption track contains those words. The media address `secret-value` stays on the clip and is not in the track. The slideshow was not opened in the browser. This is not a WCAG conformance claim.
