# Desktop updates

An update offer is a manifest plus an Ed25519 signature over the canonical JSON of that manifest. The canonical form is `JSON.stringify` with keys in this order: `product`, `version`, `channel`, `sha256`, `schemaVersion`, `restartRequired`, `minRuntime`.

Verification uses a public key the application already trusts. The manifest does not choose its own key. A changed field, a bad signature, or an installer whose SHA-256 is not `sha256` is rejected and is not installed. `minRuntime` is `major.minor.patch`. The desktop poll compares it with `process.versions.node`. A release that needs `22.12.0` is refused while this app is running `22.11.0`, and the refusal names both. A runtime of `22.13.0` still allows that release. A requirement that is not `major.minor.patch` is refused. The installed app is not replaced.

Channels are `stable` and `pilot`. A policy can pause every install, hold a fleet on one version, or follow the pilot channel. Pausing does not change open documents. A release older than the installed version is installed only when the policy names that version and its `schemaVersion` is still at least the schema already in use. An older schema is rejected so a downgrade cannot open files the current release wrote. The decision says to keep the installed app and not replace its files, and it names both schema numbers. `planRollback` returns to the previous release after a failed start only when that release did not move the document schema forward. `0.2.0` on schema 5 restores `0.1.0`. Schema 6 stays installed, and the reason does not name the versions. A failed start of the same version stays installed, and no rollback plan is written. A version `secret-value` is refused and is not repeated. Nothing is replaced. The next launch reads `failed-start.json` and writes `rollback-plan.json` with only the previous version when a restore is allowed. The failed-start record is then removed. A record that cannot be read is removed without copying its text. The installed app is still not replaced. The next poll reads `rollback-plan.json` and holds on that version unless an operator already named one. A newer release stays held. The planned older release can be installed when its schema is still in use. A plan that is not JSON is ignored, and a note in the plan is not copied into the decision. Nothing is replaced by that hold.

`restartRequired` tells the caller the process must quit and reopen before the new build is running. `planRestart` returns `wait` while documents are unsaved, and `restart` only after those edits have been saved. A paused or held release does not ask the app to quit. The desktop close handler uses that result: a waiting update keeps the window open. `recordReleaseOffer` takes a body the caller already fetched. A signed install that needs a restart is what the close handler remembers. A rejected, paused, or malformed offer clears that memory. A URL on the offer is ignored. `fetchReleaseOffer` reads one https address and records that body. A server that does not answer leaves a remembered restart in place. An address that is not https is not requested. When `SUITELEAF_UPDATE_URL` and `SUITELEAF_UPDATE_PUBLIC_KEY` are both set, the desktop process asks that address at startup and again every six hours. `SUITELEAF_UPDATE_PROXY`, when set, must be an `http` or `https` proxy. The offer and the installer download then go through that proxy. The decision does not repeat the proxy address. A value that is not an http address is not requested, and a restart already remembered stays remembered. The proxy does not sign the offer. The channel is `SUITELEAF_UPDATE_CHANNEL` (`pilot` or `stable`), a held version is `SUITELEAF_UPDATE_HELD`, and `SUITELEAF_UPDATE_PAUSED=1` pauses installs. With either the address or the key missing, nothing is requested. If that offer includes an https `installerUrl` and the decision is to install, the process downloads those bytes and keeps them only when their SHA-256 is the signed `sha256`. A mismatch clears the remembered restart and does not keep the file. The installer address itself is not signed. A kept file is written under the app's user-data `updates` directory and is not opened. `recoverPausedRollout` runs when the rollout is paused. It clears a remembered restart and deletes kept installer files whose names are the signed hash plus `.bin`. A document in that directory, including `notes.sldoc`, is left in place. Unsaved edits are not discarded. When the rollout is not paused, the kept file and the remembered restart stay. `releaseRecord` writes the offered version, whether the signature matched, the schema move, and whether the app must quit. A rejected signature names version `0.9.0`, says the signature was rejected, and leaves documents on schema 5 with no restart. An accepted `0.2.0` on schema 5 says the signature matches, documents stay on schema 5, and the app must quit and reopen. Schema 6 says documents move from schema 5 to schema 6. A signed `0.0.9` that only opens schema 4 is not a restart; the record repeats the recovery that names schema 5 and schema 4. This module does not replace `/Applications/SuiteLeaf.app`.

`update-policy.json` in the app user-data directory can set `channel` to `stable` or `pilot`, `heldVersion` to a `major.minor.patch` version, and `paused` to true or false. A field that is left out keeps the environment value. A field named `apiKey` is refused, the message does not include the value, and the poll does not start. `Stable` is accepted as `stable`. A channel that is not `stable` or `pilot` is refused the same way and does not repeat that channel. `deferUntil` is an ISO time. A signed release is held until that moment, then it can install. A value that is not a time is refused and is not repeated. A date that is not a real day, such as 31 February, is refused the same way and is not repeated. `ring` is a percent from 0 to 100. A computer whose bucket is below that number can install. A computer at or above it waits for a later ring. The decision does not include the computer's name. A ring that is not a whole percent is refused and is not repeated. When the file is missing, the environment settings are unchanged. `SUITELEAF_UPDATE_HELD` is kept only when it is `major.minor.patch`. A value `secret-value` is left out of the policy. The desktop reads that file when it starts. This test did not start the app.

The packaged desktop floor is Node.js 22.12.0, macOS 13, and Windows 10. Those match `package.json` engines and Electron 44. A runtime of `22.11.9` is older than Node.js 22.12.0. macOS 12 is older than macOS 13. Windows 6.1 is older than Windows 10. A version written as `secret-value` is not repeated. Linux has no recorded distribution floor. The update poll does not start when this runtime is older than Node.js 22.12.0, or when the operating system is below that floor. A signed offer for an older Mac is refused with `This Mac is older than macOS 13.` and the installer is not downloaded. Linux still has no distribution floor. The version text is not repeated. The app still starts. Nothing is replaced.

`apps/desktop/electron-builder.yml` sets `mac.identity` to `null`. Packages produced by `npm run package:desktop` are unsigned. Signing and notarization need credentials that are not in this repository and are not used to test this check. Model weights are not part of the manifest.

`unattendedInstallPlan` refuses that null identity. It also refuses an installer named `secret-value.sldoc`, and the refusal does not repeat that name. A signed `SuiteLeaf.dmg` whose hash matches is ready, and the check still does not replace the app. `unattendedUninstallPlan` names `/Applications/SuiteLeaf.app` and leaves `/Users/ada/Documents/Beds.sldoc` out of the removal. A path under Documents is refused, and the refusal does not repeat a document name. Neither function deletes a file. An installer name `../secret-value.dmg` is refused, and that name is not in the refusal. An app path `../secret-value/SuiteLeaf.app` is refused the same way, and it is not named for removal.

`releaseNotice` writes the offered version, the installer hash, whether the signature matched, and the document schema. Editor components are listed by name, version, and license. A model download is a later section, and each line says it is not part of the editor update. The same component cannot be both. A rejected signature is still recorded, and that notice does not name a model that was not supplied. The function does not read `node_modules` and does not replace the installed app.

`dependencyNotice` lists package names and published versions from a package description. `react` at `19.0.0` stays. A version of `1.2.3 secret-value` is recorded as `1.2.3`. A version that is only `secret-value` is counted as omitted and is not written. A `.gguf` name is omitted. The note says this is not a signature and that model files are not included. The function does not read `node_modules` and does not replace the installed app.
