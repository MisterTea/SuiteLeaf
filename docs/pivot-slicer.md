# Pivot dates and slicers

`slicePivot` copies a table. An ISO date in the date column becomes the year (`2026`), the quarter (`2026 Q1`), or the month (`2026-01`). December is `2026 Q4`. A month number past 12 stays as written. A day that is not on the calendar, such as `2026-02-31`, stays as written. A time on a real day, such as `2026-01-15T10:00:00`, uses that day, so the quarter is `2026 Q1`. A time with an offset, such as `2026-01-15T23:00:00-05:00`, uses that same calendar day. An offset that is not a time stays as written. Spaces around a real day are ignored, so ` 2026-01-15 ` is also `2026 Q1`. Any other text stays as it is. A slicer with selected values keeps only those rows. An empty slicer keeps every row. The original table is not changed.

`drillPivot` returns the original rows, including the full date, that belong to one grouped value and the slicer. It does not return the total.

A pivot with two row fields can order those groups by the subtotal. North 70 comes before South 50 when the larger total is first, and the detail rows stay with their group. The smaller total comes first when that order is chosen. A total that is not a number sorts as zero. The Grand Total stays last. A pivot with two row fields adds a Subtotal row after each value of the first field. North's quarters stay `Q1` 30 and `Q2` 40, and the North subtotal is 70. That subtotal is the sum of the original North numbers, not a sum of the quarter cells. An average subtotal for North is 70/3. The Grand Total stays the total of the original records. A pivot with one row field does not add those subtotal rows. PERCENT writes each number as a percent of the total. North 25 and South 75 become 25 and 75, and the Grand Total is 100. A total of zero says `The total is zero.` and does not repeat the row name. The source table is not changed.

A calculated field changes each source number before the totals. Multiplying Revenue by `0.1` names the column `SUM Fee` and totals North `7`, South `5`, and Grand Total `12`. Dividing each source number by `2` totals North `35`, South `25`, and Grand Total `60`. Dividing by `0` leaves those numbers, so the totals stay North `70`, South `50`, and Grand Total `120`. Adding `1` to each source number totals North `73`, from 11, 21, and 41, rather than adding 1 to the North total of 70. The source cells stay 10, 20, 40, and 50. The pivot dialog has Calculated field, Calculation, and Amount. A blank name does not add a calculated field.

A calculated field can also be one column minus another. Revenue 10 and 20 with costs 4 and 5 totals `SUM Margin` as 21 for North. A cost of `secret-value` is left out of the total, and that text is not in the result. The source rows stay as they were. The same two columns are refused with `Choose two columns for the calculated field.` The pivot dialog has Subtract columns, Left column, and Right column. A blank name stores no difference. A name `secret-value` on the same column is refused, and that word is not in the message. The pivot panel was not opened in the browser.

A second summary adds another column for the same row groups. Sum and count of Revenue are North `70` and `3`, South `50` and `2`, and Grand Total `120` and `5`. The count includes a non-numeric cell and skips an empty one. The source numbers stay 10, 20, 40, and 50. The pivot dialog calls that control Also summarize. A column split still uses one summary.

The pivot definition can store `dateColumn`, `dateGroup`, `slicerColumn`, and `slicerValues`. Reading that definition back from JSON keeps them. The pivot dialog sets them. Date field and Group dates store a year, quarter, or month group. Slicer field and Slicer values store the kept values. No date group and no slicer leave those fields off the definition.

A linked chart keeps the source name, `From Plot fees`, when the viewer cannot open that spreadsheet. The bars, the source id, and the numbers are left out, and the snapshot says the bars are not included. The export also says `Snapshot of Plot fees. Taken 2026-10-31T18:00:00.000Z. These values are a copy, not a live link.` That sentence does not include the source id. A copy with no stored time says the time was not recorded. Updating the chart from a spreadsheet that is still there stores the time of that copy. A clock value that is not a time, including `secret-value`, leaves the previous time `2026-10-30T00:00:00.000Z` in place. The bars from the spreadsheet are still copied. That word is not stored on the chart. A viewer who can open the source still gets the bars. The chart object passed in is not changed. A newer copy waits until Accept update. Until then the open chart keeps its bars, and the notice is `A newer copy is waiting. The chart was not changed.` Reject update leaves those bars. A viewer who cannot open the source gets `You cannot view this spreadsheet. The bars are not included.` and no new bars. That notice does not include a label from the spreadsheet.

A named table stores its header row and the last data row. `Sales[Revenue]` is that column from the first data row through the last. Adding one row makes the reference one row longer. A chart or pivot whose source is exactly the whole table grows with it. A value written in the row immediately under the table lengthens it the same way. A value two rows below, or in a column beside the table, does not. The written cell is not copied onto the table. The spreadsheet applies this when a range is written. A source on another sheet stays as it was. A missing column says `That column is not in this table.` A table that is not on this sheet says `That table is not on this sheet.` Those sentences do not name the column or the table. The error does not change those sources. The table and the chart passed in are not changed. Reading the sheet file back from JSON keeps the grown table. The spreadsheet lists that table as `Sales A1:C4`, and after one added row as `Sales A1:C5`. Removing one row lists `Sales A1:C3`. A chart that covered the whole table follows that shorter end. A chart on another sheet stays. Removing more rows than the table has says that would remove the header, and the table stays. A table with only its header says it has no rows. Inserting one row under the header lengthens the list from `Sales A1:C4` to `Sales A1:C5`. A chart that covered the whole table follows that end. A row on the header, or a row past the table, is refused, and the table stays. `insertTableCells` moves the cells in those columns down. A cell in a column outside the table stays on its row. The grid passed in is not changed. Formulas move with their cells. A reference to a row that moved shifts by the same number of rows, including a locked row such as `$C$2` becoming `$C$3`. A reference above the inserted row stays. Text inside quotes stays as written. Deleting a data row moves the cells below it up. A formula that pointed at the deleted row becomes `#REF!`. A formula that pointed at a row below shifts up. Opening the sheet asks for a thin border around that table range. The border request does not include the table name. The painted grid was not opened to look at the line. After a row is inserted or deleted, `tableAfterStructure` moves the table bounds. A row inserted above `Sales` changes `A1:C4` to `A2:C5`. A row inserted inside it changes the end to `C5`. A row below it leaves `A1:C4`. Deleting one data row leaves `A1:C3`. Deleting every row of the table removes the table. This does not move the cells; the grid command does that. `=SUM(Sales[Revenue])` becomes `=SUM(C2:C4)`. After one added row it becomes `=SUM(C2:C5)`. A quoted `Sales[Revenue]` stays quoted. A table on another sheet is not used. A missing column says `That column is not in this table.` A missing table says `That table is not on this sheet.` While the formula is typed, `Sales[Revenue]` is noted as `Sales[Revenue] is C2:C4.` The stored formula is not rewritten. A quoted `secret-value` is not in that note. The spreadsheet was not opened for this check.

A pivot with one row field can sort by the row total. North `70` and South `50` in descending value order are North then South. Ascending value order is South then North. Label order descending is South then North. With no sort stored, the labels stay ascending, North then South. The Grand Total stays last. A non-numeric `secret-value` is not a row and is not in the result. The source numbers stay as they were. Two row fields still use label order for a value sort. The pivot dialog’s Sort rows control stores that order. Values high to low is `{ by: "value", direction: "desc" }`. An unknown choice is left out. Show source rows lists the original dates for one group. For 2026 and a North slicer, that list is `2026-01-15, North, 10` and `2026-03-02, North, 5`. A South row whose cell is `secret-value` is not listed, and the note does not repeat that word. An empty name says to name the group. The pivot panel was not opened in the browser.
