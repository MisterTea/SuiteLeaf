# Accessibility checks

`checkDocument` walks a SuiteLeaf document and returns notes with a path of child indexes from the document root. An `automatic` note is one the check decided: no heading, a heading that skips a level, an image with no alternative text, a link with no text or with text such as "click here", and a table whose first row has no header cell. An image with empty alternative text, and every run of colored text, are marked `automatic: false`. The color note does not include the color value, and a link note does not include the address. Those need a person to decide whether the image is decorative and whether color is the only way to understand the text. A header cell in the first row that has no words is noted as empty. The note does not include the text of another cell. A heading whose only characters take no space is noted as `This heading has no text.` A link whose visible words are `learn more` does not say where it goes. The address is not in that note. A header cell of only an invisible character is empty. A heading with no words is noted as `This heading has no text.` A paragraph `secret-value` under that heading is not in the note. A heading `Beds` is not that note. An image description that ends in an image file extension is noted as a file name. The note says to write what the image shows and does not include `secret-value.png`. A description `Tomato beds` is not that note.

The document toolbar opens these notes. Each note is a button. The button names the note and the text of the node it points at, such as `North`. Choosing it puts the caret at that node. A path that does not exist does not move the caret.

The accessibility matrix has twelve cells: keyboard, screen reader, zoom, high contrast, reduced motion, and touch, each for the web client and the desktop window. Screen readers, zoom, and touch are untested. High contrast on the web is partial: `prefers-contrast: more` sets black text, a white surface, and a black border. Reduced motion on the web is partial: slide entrance and deck transition animations are turned off. The app stylesheet also shortens animation, transition, and smooth scrolling when `prefers-reduced-motion: reduce` is set. That preference was not turned on. The desktop window was not checked; it loads this web client. No cell is a pass. This is not a WCAG conformance claim.

The spreadsheet toolbar button Accessibility checks column headers. A column with a value below the first row and no header is named by its column number. The cell value is not shown. A sheet with no name is labeled Sheet, and the sheet id is not shown. Choosing that note selects the header cell of the column. A cell whose value is `#REF!` is named by its address, as `B2 shows #REF!.` The formula text is not shown. Choosing that note selects that cell. The spreadsheet was not opened in the browser. The same panel lists the first cells as text fields. A header `Crop` is field `A1`. The cell under it is field `Crop row 2`. Changing that field to `Bean` reports row 1, column 0, and `Bean`. The grid passed in still says `Tomato`. A formula error outside those first rows and columns is also a field, so `G21` showing `#DIV/0!` can be edited. The formula text is not in the field. A later sheet is included. Fees `A1` showing `#DIV/0!` is the field `Fees A1`, and the write goes to that sheet. The sheet id is not in the label. The formula text is not in the field. A workbook with one sheet still labels the field without a sheet name. The painted grid was not used for that check. A Word export of a heading, an image, and a table keeps the heading text, the image description, the header cell, and the body cell. The heading is a Heading 1 style and the header row is marked as a header. File → Export PDF writes the heading, the citation, the image description, and each table row as text, in that order. That file has a structure tree. The heading is `H1`, the citation paragraph is `P`, the image description is `Figure`, and the table is `Table`, the row is `TR`, the header cell `Crop` is `TH`, and the body cell `Tomato` is `TD`. A blank cell is left out. It is not a PDF/UA file. A print to PDF is a different path. Slide reading order is a separate slide export. Nothing here is a WCAG conformance claim. Before that PDF is written, the index is rebuilt from the marks. A stale line `secret-value` is replaced by `Tomato, section 1` and is not in the file. The document that was exported still has the stale line. It is still not a PDF/UA file.

A stored cell outside those first rows and columns is also a field. `G21` holding `Beds` can be changed to `Paths`. After 40 of those cells, the rest are counted and not listed. The note is `2 more cells are outside this list.` A cell value that did not fit is not in that note. The grid passed in is not changed. This is not a WCAG conformance claim.

A dropdown chip color that is not `#` plus six hex digits cannot be checked. The note is `This chip color is not a hex color.` The color is not repeated. A listed chip color still gets black or white text that clears 4.5:1. This is not a WCAG conformance claim.
