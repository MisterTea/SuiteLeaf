# Office compatibility run

This is how SuiteLeaf measures what survives a full Office round trip (WP-012). For the corpus import inventory, see [office-imports.md](office-imports.md).

```sh
npm run test:office-compat                    # generated fixtures, LibreOffice as reference
npm run test:office-compat -- --no-reference  # SuiteLeaf stages only
npm run test:office-compat -- --force         # ignore saved results
```

`npm test` also runs the same fixtures without a reference application (`tests/compat/compat-run.test.ts`). That is the CI gate.

## The sequence

Each file goes through these stages, in this order:

1. **source**: the Office package as generated.
2. **import**: the SuiteLeaf model.
3. **edit**: one new paragraph, cell, or text box holding `SuiteLeaf edit marker`.
4. **native**: the native file saved and opened again.
5. **export**: SuiteLeaf's Office package, read as another application would read it.
6. **reimport**: that export imported again.
7. **reference**: LibreOffice reopens the export.

LibreOffice runs in a throwaway profile with macros and link updates turned off. Every Excel formula is recalculated on load, so the values come from LibreOffice and not from the results SuiteLeaf cached. Original files are never changed.

## Dimensions and outcomes

Content, formulas and their values, comments and revisions, objects, fonts, layout, and media are scored separately. A fixture declares probes, such as a sentence, a formula with its expected value, a comment, a table, a font, a page count, or a picture's hash. Each probe is checked at every stage that can see it.

| Outcome | Meaning |
| --- | --- |
| `pass` | Every probe was seen after the source stage and was never missing. |
| `loss` | The probe was present in the source and missing at a later stage. The report names that stage. |
| `incomplete` | The source did not show the probe, so the fixture proves nothing. |
| `unavailable-reference` | Only a reference application could have measured it, and none ran. |
| `not-measured` | The fixture has no probe for this dimension, or no stage could see it. |

Only `pass` is a pass. A screenshot is never evidence in this run.

## Fixtures

The fixtures are generated by independent libraries: docx, SheetJS, and PptxGenJS. They are never generated by SuiteLeaf's exporters. They contain no third-party content.

| Fixture | Exercises |
| --- | --- |
| `docx-report` | Heading, bold Calibri text, table, picture, comment, tracked insertion, page break |
| `xlsx-budget` | Two sheets, `SUM` and a cross-sheet formula with expected values, cell comment, Calibri |
| `pptx-plan` | Two slides, Calibri title, table, picture, speaker notes |

The manifest written by each run records each fixture's generator version, features, probes, classification, spec hash, and the SHA-256 of that run's bytes. The generators write timestamps, so identity comes from the spec hash.

## Results, resume, and fingerprints

Results go to `datasets/validation/office-compat/results.jsonl`. That directory is ignored by Git. A saved result is reused only if three things are unchanged:

- the converter fingerprint, a hash of the import, export, and compatibility sources;
- the fixture spec;
- the reference application version.

Anything else runs again, so an interrupted run resumes safely. `summary.md` and `manifest.json` are written beside the results. In GitHub Actions, the summary is also added to the job summary.

## Release-blocking differences

For a `supported` fixture, these block a release and set exit code 1:

- a `loss` or `incomplete` dimension that the tolerated list does not cover;
- a SuiteLeaf refusal or timeout;
- a reference application that failed or timed out on the export.

`TOLERATED` in `packages/core/src/compat/report.ts` gives each tolerated difference an owning work package, the limit, and the user document that states it. The summary lists any tolerated entry that no longer matches a loss, so it can be removed once its repair lands.

The list is empty. Until 2026-11-04 it held one entry: DOCX run fonts were dropped on import, so Calibri text came back as Arial. WP-014 fixed that.

## Limits of this run

- Microsoft Word, Excel, and PowerPoint are not driven as reference applications. LibreOffice is the reference.
- LibreOffice reads DOCX text and page count, XLSX values, and PPTX slide count. It does not read fonts, comments, or slide text.
- Layout is measured as a page or slide count, not by comparing rendered pages.
- The large external corpora in `datasets/` still go through `scripts/office-roundtrip-report.mjs`, which reports features by owner but not these dimensions.
- XLSX pictures and PPTX comments are not in the fixtures, because the generators used cannot write them.
