# Backups

A SuiteDrive backup is a directory of content-addressed blobs plus `manifest.json`. It is written only when every file version's bytes, and every chunk of those bytes, are already on this node. A missing chunk aborts the export and leaves no directory. A folder restore that finds a content id it cannot read says `A content id in this backup is not a content id.` That id is not in the sentence, and the live database is not changed.

`POST /api/admin/backup` seals a due backup of the live files. The schedule, key file, sealed path, and copy path come from the environment. The response says `No backup has been recorded.` and `wrote` is true. Opening the copy returns the file bytes `keep this`. That text is not in the response. A second request in the same day writes nothing and says `The last backup is still inside the schedule.` A later day writes another sealed copy and leaves the earlier copy in place. The new file name uses the time's digits. The earlier copy still opens to its own bytes. A key that is not 32 bytes says `The backup key must be 32 bytes.` The status GET still only reports freshness.

`manifest.json` records `recordedAt`. That time is when the archive was assembled. It is not a promise about how recently a restore was rehearsed. `backup_freshness` reads that time and a successful `drill.json`. It reports the file count and the drill time. It does not report content hashes or the database file. A `drill.json` that is not a drill record returns `That restore drill record cannot be read.` The text in that file, including `secret-value`, is not in the error. When `SUITELEAF_BACKUP_EVERY_HOURS` is set, the same report says whether that many hours have passed. A backup recorded at `2026-11-01T00:00:00.000Z` is still inside a 24 hour schedule at noon that day, and it is due at `2026-11-02T00:00:00.000Z`. No recorded backup says `No backup has been recorded.` A last time of `secret-value` says `The last backup time is not a time.` and that word is not repeated. A schedule that is not a number of hours from 1 to 168 says `The backup schedule must be from 1 to 168 hours.` `export_if_due` writes the backup when that decision says one is due, and leaves no directory when the last backup is still inside the schedule. A current time of `secret-value` says `The current time is not a time.` and writes nothing. `export_sealed_if_due` does the same and then seals the backup. The plaintext directory is removed. The sealed file is copied outside that file's directory. Opening that copy with the key returns `keep this`. A key that is not 32 bytes says `The backup key must be 32 bytes.` and leaves no directory. This decision does not write a backup when it is not due. Admin shows that report when `SUITELEAF_BACKUP_DIR` is set. The directory is not taken from the request. A single-node library redirects away from Admin, so this note was not opened in the browser. A recorded time that is not a timestamp is shown as `The backup time is not a date.` or `The restore test time is not a date.` The other text is not repeated. A restore test timestamp that is earlier than the backup time says that restore test is older than this backup, and the elapsed time of that older test is not shown as if it measured this backup.

Restore checks every blob hash before it copies anything into a live blob store. A dry run reports how many blobs would be copied and does not write. A missing or altered blob stops the restore, and the live store is left as it was. A changed blob says `That backup blob is corrupt.` The blob id is not in that sentence. A backup whose kind is not SuiteLeaf says `That backup is not a SuiteLeaf backup.`

`restore_contents` copies only the requested content hashes and the chunks those contents need. The same check runs first. A requested hash that is not in the manifest copies nothing. The notice is `That backup does not contain that content.` and does not include the hash. A content id in the manifest matches whether it is written in upper case or lower case. Other files in the archive are not copied. A backup name that is not a single directory is refused with `That backup name is not a single directory.` and that name is not repeated.

`restore_clean` writes every file, version, and grant from that snapshot into a database that has no files yet. It checks the archive first. A version whose content is not listed says `That file content is not in this backup.` The content id is not in that sentence, and nothing is copied. A content id that cannot be read says `That backup content id cannot be read.` A restored content that cannot be read back says `That restored content is missing.` A drill that cannot reassemble a listed content says `That drill content is missing.` None of those sentences include the content id. A database that already has a file is left as it is, and none of the archive's bytes are copied into that attempt. Content bytes for each restored version are read back from the restored store. A missing account named by a grant is copied without a password, password hash, token, or private key. The organization sign-in row is copied when the empty database has none, and its client secret is left out. This does not start a node, and it does not copy a node identity or a swarm key.

`restore_folder` reads one folder from the backup's database snapshot and writes that folder and the missing files inside it into the live database. A file that is already on this node keeps its name and its current version. A comment on a missing file comes back with that file. A comment id that is already on this node stays as it is. A comment on a file outside the folder is not written. The comment text is not in the restore summary. Their content hashes are copied. Grants on that folder and those files are copied with them. A file that is not in that folder keeps its name, its current version, and its grants. When the snapshot has a `user` table, a missing account named by one of those grants, or named as an item owner, is copied. A password, a `passwd` column, a password hash, a token, or a private key on that account is not copied. An account that already exists is left as it is. An account that is neither a grant nor an owner is not copied. Priya owns Tomatoes, so her account is copied. Her password and an `apiKey` are not copied. Her name and email are. Noor is still not copied. The archive is checked before those rows are written. `restore_folder_copy` writes that folder under new ids, so the live folder keeps its id. The copy is `copy-beds`, and its file stays inside that copy. A second copy is refused. A folder id that is not in the backup is refused without repeating that id. `plan_file_restore` names the missing file and how many versions it has, and writes nothing. `restore_file` writes one missing file, its versions, and its content. A file that is already on the node stays as it is. A folder id is refused. A file id that is not in the backup is refused without repeating that id. Another file keeps its current version. `restore_version` copies an older version onto a file that is already on the node and leaves the current version in place. A second copy of that version is refused. A version id that is not in the backup is refused without repeating that id. This is another directory on this machine, not a remote storage service, and it does not start a node.

`record_restore_drill` restores the archive into a scratch store, reassembles every content, and writes `drill.json` only when that succeeds. `drilledAt` is the drill time. `recordedAt` stays the time the archive was assembled. `elapsedMs` is the wall time of that one successful drill on the machine that ran it. It is not a recovery-time target, and a failed drill does not record a time. A failed check does not write `drill.json`. The scratch store is removed and no live blob store is changed. On a passing drill every content listed in the archive was reassembled, so this fixture's missing content count is zero. That is not a promise about a larger outage.

This archive is not a replica. Replication copies the node's current database, including deletions and holes. The backup directory is a separate copy of the file bytes that were present at `recordedAt`.

`export_backup_from_database` checkpoints the live SuiteDB with SQLite's backup API and stores that snapshot as `database.sqlite`. A write that happens after the checkpoint is not in the archive. The manifest records the snapshot's hash. Restore checks the hash before it copies any blob. A changed database file stops the restore. Opening the snapshot does not recreate accounts on a running node.

`export_incremental` writes a later archive that stores only blobs the previous archive does not already have. Its manifest names the BLAKE3 of that previous `manifest.json`. `verify_chain` accepts Monday, Tuesday, and Wednesday in that order. Tuesday alone, or Monday followed by Wednesday, is a chain gap. Changing Monday's recorded time after Tuesday was written is also a gap. The check does not copy blobs into a live store. `restore_chain` copies Beds, Paths, and North after Monday, Tuesday, and Wednesday all check. A dry run reports the three contents and writes nothing. Monday then Wednesday writes nothing, including after Monday's recorded time is changed. These are directories on this machine, not a remote storage service. This does not start a node.

`attach_database` stores a SuiteDB snapshot on an incremental archive and records its hash. `restore_chain_database` checks Monday and Tuesday, then writes that snapshot into a database that has no files yet. Beds is read from Monday's blobs and Paths from Tuesday's. A changed snapshot is refused and copies nothing. A database that already has a file is left as it is, and those blobs are not copied. Sam is copied as an editor without the password `secret-value`. The organization issuer is copied and the client secret is not. This does not start a node.

Not in this archive yet:

- Node identity and swarm keys
- Desktop recovery drafts under `~/.config/suiteleaf`

Those have to be backed up on their own. Restoring blobs does not by itself recreate accounts or sharing.

`restore_auth_config` copies the `organization` row from an `auth_config` table in an opened snapshot when the live database has no such row. The issuer `https://idp.example`, the audience `suiteleaf`, and an idle time of 1800 seconds are copied. A client secret is not copied. A row that is already on the live database is left as it is. This does not restore a node identity or a swarm key.

`seal_backup` encrypts a finished backup directory into one file with a 32-byte key the caller supplies. `open_sealed` decrypts into a new directory and runs the same hash check. A wrong key or a changed byte leaves no directory. The key is not a passphrase, and this is not end-to-end encryption of documents on the node. Losing the key means that copy cannot be opened. `store_sealed` copies that sealed file into a different directory and keeps the copy only when the same key opens it. A copy in the sealed file's own directory is refused. A wrong key removes the copy. `resume_sealed_copy` copies a limited number of bytes and continues on a later call when the destination is still a prefix of the sealed file. A destination that is not that prefix is left unchanged. The key is checked only after every byte is copied, and a wrong key removes that finished copy. A partial copy is not opened. This is another directory the operator chooses, not a remote storage service. `retention_plan` names which backup directories are old enough to delete. The newest copy is always kept, including when it is older than the cutoff. A copy with no recorded time is kept. `apply_retention` deletes only the directories the plan lists, and it refuses a plan that would leave no `manifest.json`. Retention does not copy the archive. The drill's `elapsedMs` is separate from retention.

Sealing a file that is already there says `That sealed backup already exists.` The path is not in that sentence. A backup directory that is already there says `That backup destination already exists.` An independent copy that is already there says `That independent copy already exists.` These sentences do not include the key.
